# 运行日志落盘 Spec

## 背景

potatocode 的 6 个模块已经通过标准日志接口打了 13 处记录：上下文压缩的关键节点（信息级 6 处，如摘要请求撞长度上限后的重试、摘要完成后保留的条数）、工具结果落盘失败等可降级异常（告警级 6 处）、以及上下文压缩失败时的完整堆栈（异常级 1 处）。

但项目从未建立任何日志出口——没有输出目标、没有级别、没有落盘位置。后果分三层：

- **信息级（6 处）被静默丢弃**。压缩链路的每一步决策过程完全不可见，"这一轮为什么没触发压缩""摘要丢了几组消息"只能靠读代码推断。
- **告警级（6 处）落到进程的标准错误流**。而 TUI 全屏接管终端，写进去的内容要么被界面覆盖，要么造成花屏，实际看不到。
- **异常级（1 处，上下文压缩失败）连同堆栈一起丢失**。压缩失败恰恰是最需要排查的一类故障——它由 provider 拒绝、摘要输出格式异常等外部原因触发，没有堆栈就只能猜。

MCP 模块另有 5 处告警/连接信息走的是直接向标准错误流打印，同样命运。"MCP server 为什么没连上"是这类信息里最典型、也最难排查的一个。

现状：`.potatocode/sessions/<session_id>/` 已经为每个会话保存工具结果落盘产物，但没有保存任何运行日志。

## 目标

- 应用运行期间产生的日志有唯一、可靠的落盘出口，不依赖终端
- 每个会话的日志与该会话的其它产物收在同一目录，可按会话整体回溯或归档
- 启动全过程的日志都被覆盖，包括配置加载之前发生的事件
- 日志落地不引入密钥或用户代码内容的新泄漏面
- 排查时能临时提高详细度，无需改动代码或配置文件

已接受的取舍：配置非法导致启动失败时，仍会留下一个只含错误日志的会话目录。

## 功能需求

- **F1 会话日志文件**：应用为每个会话在其会话目录下建立日志文件，记录该会话从启动到退出的全部自有日志。路径形如 `.potatocode/sessions/<session_id>/session.log`
- **F2 启动早期覆盖**：会话标识的生成先于配置加载，使配置错误、MCP 连接失败、权限引擎降级等启动早期事件也进入该会话日志
- **F3 默认详细度**：应用自身的日志默认记录到信息级（含）以上；更详细的调试级默认不记录
- **F4 详细度可临时调整**：通过环境变量把详细度提升到调试级，无需修改代码或配置文件
- **F5 第三方日志隔离**：只采集应用自身的日志，不采集依赖库（LLM SDK、HTTP 客户端、MCP SDK 等）的日志，即使详细度已提升到调试级
- **F6 异常堆栈落盘**：以异常级记录的调用，其完整堆栈写入日志文件
- **F7 MCP 输出统一**：MCP 模块的告警与连接信息不再直接写标准错误流，改走日志出口，从而进入会话日志
- **F8 日志格式**：每行含时间、级别、来源模块、消息四要素；文件编码为 UTF-8，中文内容不乱码
- **F9 出口收尾**：应用退出前刷新并关闭日志文件，保证尾部内容不残缺

## 非功能需求

- **N1 不阻塞交互**：日志写入不得阻塞 TUI 事件循环，或引起可感知的卡顿
- **N2 线程安全**：多线程并发记录（会话状态对象内部有锁保护的临界区可能被工具线程与主循环同时进入）不产生交错、错行或丢失
- **N3 不扩大泄漏面**：日志内容不含 API 密钥；不解开依赖库日志，以免把完整请求体（用户的对话与代码内容）带入文件
- **N4 故障不放大**：日志出口自身初始化失败（如目录不可写）不得阻断应用启动，需降级并继续运行
- **N5 会话间不串扰**：并发运行多个实例时，各自只写入自己的会话日志，互不干扰

## 不做的事

- **不在 TUI 内展示日志**。不做 `/logs` 命令或日志面板——日志文件的消费者是开发者，不是终端界面
- **不做滚动、按大小切分或过期清理**。只记录应用自身日志，单会话写入量有界；多实例各写各的文件，不存在争抢
- **不采集依赖库日志**，即使用户已把详细度提升到调试级
- **不提供配置文件里的日志级别项**，只走环境变量
- **不改动现有 13 处日志调用的内容与级别**
- **不做结构化（JSON）日志格式**
- **不改变配置错误、权限降级在终端上的可见提示**。这类信息是给人看的启动反馈，不是日志，保持现状

## 验收标准

- **AC1**（F1）启动一次真实会话并发起一轮对话后，该会话目录下存在日志文件，且内容含该会话的运行记录
- **AC2**（F2）故意用非法配置启动，进程退出后，对应会话日志中存在记录该配置错误的条目
- **AC3**（F3）默认启动时，信息级记录出现在日志文件中
- **AC4**（F3/F4）默认启动时，调试级记录不出现在日志文件中；设置环境变量后，调试级记录出现
- **AC5**（F5）让依赖库产生日志，这些日志不出现在会话日志文件中
- **AC6**（F6）触发一次上下文压缩失败，日志文件中能找到含完整堆栈的记录
- **AC7**（F7）MCP 连接失败时，告警出现在会话日志文件中，且不再只写标准错误流
- **AC8**（F8）日志每行含时间、级别、来源模块、消息；中文内容无乱码
- **AC9**（F9）进程正常退出后，日志文件尾部不残缺（最后一条记录完整成行）
- **AC10**（N4）日志目录不可写时，应用仍能启动并进入交互
- **AC11**（N5）并发启动两个实例，各自日志文件中不含对方会话的记录
- **AC12** 测试基线不回归：除本次改动前既有的 2 个失败项外，无新增失败
