# 工具遍历范围修订 Plan

## 架构概览

本次改动落在**工具包内部**，不触及 agent 编排层、provider 适配层、权限引擎、TUI。改动由三部分组成：

- **新增一个排除判定模块**——把「哪些目录不值得搜」这条规则从两个工具里抽出来单独成模块，供两个遍历类工具共用。规则本身是纯函数式的：输入一个路径与搜索根，输出"是否排除"，不读文件、不碰磁盘、无状态。
- **两个遍历类工具各加一处过滤**——在既有遍历循环里插一道判定，把命中的路径分成"进入结果"与"跳过"两拨。两个工具的插入位置不同，但用的是同一个判定函数。
- **搜代码内容工具的逐行扫描改写**——把"每切一行重扫剩余缓冲"的循环换成"每块只切一次"，输出逐条保持不变。

选择的是一条**最小侵入**的路线：不改动两个工具现有的遍历调用方式（仍用 pathlib 的 glob / rglob 产出候选路径），只在候选路径产出后、进入昂贵操作前加一道过滤。这样既不重写 glob 模式匹配语义，也保留了 pathlib 的既有行为（尤其"不跟随目录软链接"，见「不做的事」）。

## 核心数据结构

### `EXCLUDED_DIR_NAMES: frozenset[str]`

内置的固定噪声目录名集合，值为 `{"__pycache__", "node_modules"}`。用 `frozenset` 而非 `list`：判定是热路径上的成员检查，集合查找是 O(1)；同时冻结后不可被运行时修改，与"名单内置固定、不可配置"（spec F1）一致。

隐藏目录不在此集合中——它们由"名字以 `.` 开头"这一条规则覆盖，不逐个列举。这样新增任何一种工具缓存目录（`.tox`、`.next`、`.cache`……）都自动被覆盖，无需维护名单。

### `is_excluded(path, root) -> bool`

排除判定的唯一对外接口。

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | `Path` | 待判定的候选路径（遍历产出的一条命中） |
| `root` | `Path` | 本次搜索的根目录 |

返回 `True` 表示该路径位于被排除的目录内，调用方应跳过。

### `_iter_lines(file, max_line_chars) -> Iterator[tuple[int, str, bool]]`

**签名与产出契约完全不变**：逐行产出 `(行号, 行文本, 是否超长未完整)`。本次只重写函数体内部的切分方式，产出序列必须与改动前逐条一致（AC8）。

## 模块设计

### `tool/exclude.py`（新增）

**职责：** 定义默认排除规则，并提供判定入口。

**对外接口：**

- `EXCLUDED_DIR_NAMES: frozenset[str]` —— 固定噪声目录名集合。
- `is_excluded(path: Path, root: Path) -> bool` —— 判定候选路径是否落在被排除目录内。
- `_is_excluded_dir(name: str) -> bool` —— 判定单个**目录名**是否命中规则（隐藏目录 或 在固定名单中）。

**判定语义（对应 spec F1/F2）：**

1. 求 `path` 相对 `root` 的路径；若 `path` 不在 `root` 之下，返回 `False`（见「技术决策」第 6 条）。
2. 取该相对路径的**目录分量**——`relative_to` 结果去掉最后一段（文件名本身）。**文件名不参与判定**：根目录下的 `.foo.py` 是普通文件，不该被排除。
3. 任一目录分量命中 `_is_excluded_dir` 即返回 `True`。

**为什么取"相对 root 的分量"而不是绝对路径的分量**：这是 spec F2 的逃生口所依赖的机制。若按绝对路径判定，那么无论搜索根指向哪里，`.venv` 这个分量都存在于绝对路径中，规则永远生效，模型就再也无法搜进依赖目录。改成相对 root 判定后，当搜索根本身就是那个被排除的目录时，该目录名不在"根之下的分量"里，规则自然不生效——**"默认不进去"与"显式要求进去"由此可区分，且无需新增任何参数**。

**依赖：** 仅标准库 `pathlib`。

### `tool/glob_tool.py`（修改）

**职责不变。** 在既有遍历循环中，于 `is_file()` 判定之后、把路径计入结果**之前**插入排除判定：

- 排除判定必须在计数之前——被排除的命中**不占用 100 条结果配额**，这正是 spec AC6「配额保真」要求的。若放在计数之后，噪声仍会挤掉项目自身的文件。

**依赖：** 新增对 `tool/exclude.py` 的依赖。

### `tool/grep_tool.py`（修改）

**职责不变。** 两处改动：

1. **遍历循环中插入排除判定**，位置在 `is_file()` 之后、**打开文件之前**。这个位置是关键——spec F1 的收益主要来自"不去读被排除目录里的文件"，放在 `open()` 之后就只能过滤输出、省不下开销。
2. **重写 `_iter_lines` 的切分循环**（见下）。

### `tool/grep_tool.py` 的 `_iter_lines` 重写

**现状的问题：** 每切出一行，都要把剩余缓冲重新扫描一遍：

```
while "\n" in buf:
    line, buf = buf.split("\n", 1)   # 每次调用都复制一遍剩余缓冲
```

一块 64KB 的缓冲里若有约 1000 行，就要切 1000 次，每次复制平均约 32KB 的剩余内容。扫 114 万行时这层常数开销把吞吐压到朴素按行迭代的 40%。

**改法：** 每块只切一次，未完成的行尾留到下一块：

```
parts = buf.split("\n")   # 整块一次切完
buf = parts.pop()         # 尾段是未完成的行，留给下一块拼接
for line in parts:
    ...产出...
```

**必须原样保留的两处分支**（AC9 要求超长行语义不变，这两处正是该语义的实现处）：

- **超长行守卫**——当缓冲内没有换行符且长度超过阈值时，产出截断前缀 + 标注，并清空缓冲。它保证缓冲不会随行长度无界增长。
- **文件末尾的收尾分支**——原样保留（注意它产出的 `too_long` 恒为 `False`：因为守卫已保证此处的缓冲必无换行且不超阈值）。

**内存上界不变：** 缓冲上界 = 阈值（超长行守卫会把超限缓冲清空）+ 一块读取量。新旧实现的峰值内存同阶；`split` 一次性产出的所有行合计约等于原缓冲大小，不额外膨胀。

**产出等价性：** 已用 1,148,661 行真实语料对照新旧实现，行号序列与命中集合**逐条相同**（均为 95 处命中）。task.md 中会把这对照固化为测试（AC8）。

## 模块交互

改动后的调用链（以搜代码内容为例）：

```
GrepTool.execute(args)
   │
   ├─ 解析参数、编译正则
   │
   └─ for p in root.rglob(glob_pat):        ← 遍历方式不变
        │
        ├─ p.is_file()?          否 → 跳过
        │
        ├─ exclude.is_excluded(p, root)?   ← 新增的一道判定（F1/F2）
        │        是 → 跳过（不打开文件）
        │
        ├─ 打开文件
        │
        └─ for 行 in _iter_lines(...):     ← 函数内部切分方式已改写（F4）
             命中 → 计入 hits，达到 100 条上限即中断
```

按模式找文件的链路同构，区别只有两处：候选路径来自 `root.glob(pattern)`；排除判定放在"计入结果"之前（而非"打开文件"之前）。

两个工具都**只依赖 `exclude.is_excluded` 这一个接口**，不感知规则细节。将来若要调整排除范围（例如把 `.claude` 移出排除），只改 `exclude.py` 一处，两个工具同时生效。

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 排除逻辑放哪 | 独立模块 `tool/exclude.py`，两个工具共用 | 同一套规则被两处调用；抽出来避免复制粘贴后各自漂移，也让判定能脱离工具单独单测 |
| 判定粒度 | 只看**目录名**，不读文件内容、不看大小 | F1 的规则就是名字级的；无需 I/O 即可判定，便宜且结果确定 |
| 判定基准 | `path.relative_to(root)` 后的**目录分量** | F2 的逃生口靠这条实现（见 `exclude.py` 模块设计）；同时排除文件名本身，避免误伤根下的 `.foo.py` |
| glob 的过滤位置 | `is_file()` 之后、**计数之前** | 被排除的命中不能占 100 条配额，否则噪声照样挤掉项目文件（AC6） |
| grep 的过滤位置 | `is_file()` 之后、**`open()` 之前** | F1 的收益主要来自不读依赖目录；放在 open 之后就只剩过滤输出、省不下开销 |
| 是否重写遍历调用 | **不重写**，保留 `Path.glob` / `Path.rglob`，只在其产出上加过滤 | ① 保留 pathlib 既有语义，尤其"不跟随目录软链接"（spec §不做的事 要求保留）；② 免去把 glob 模式翻译成目录前缀+文件名匹配的工作，兼容风险最低；③ 实测枚举整仓 5282 个文件的成本仅 0.10s，过滤后完全不是瓶颈 |
| `_iter_lines` 改法 | 每块一次 `split("\n")`，尾段 `pop()` 留给下一块 | 消除逐行重扫；已用 114 万行语料对照，行号与命中逐条一致 |
| 超长行守卫与 EOF 分支 | ~~**逐字保留不动**~~ → **2026-09-27 修订：守卫分支必须改** | 原判断"这两处就是超长行语义的实现，保留即保持 AC9"是错的：守卫分支本身有缺陷——跨多块的超长行会被拆成多条记录、行号递增，后续行号整体错位（详见 `evidence/verification.md` AC9 补录）。AC9 要的是"超长行语义**保持**"，而错位行号与该目标直接冲突，"保留"反而是违背 AC9。EOF 分支仍逐字保留。 |
| 超长行剩余部分的处理 | 整段丢弃，用 `dropping` 状态标记 | 前缀已产出并标注 `too_long`，剩余部分既不能当新行产出（会涨行号），也不值得继续搜索（已告知模型"未完整搜索"）。丢弃期间缓冲每块清零，内存上界不变 |
| 路径不在根之下时 | 返回 `False`（不排除） | **与 ch06 权限层的"安全默认"方向相反，这是有意的**：权限层失败必须收紧（绝不静默放行），而这里是搜索**可见性**过滤，静默**隐藏**用户数据才是更糟的失败。该分支实际不可达（两个遍历 API 产出的路径必在根下），仅作防御 |
| 排除名单是否配置化 | 否，内置 `frozenset` 常量 | spec §不做的事 明确不开放配置；YAGNI |
| 结果条数上限 | 保持 100 不变 | 本次只保证这 100 条不再被噪声占用；调上限是另一个问题 |

## 自检

**spec 覆盖**——每条功能需求在架构中的归属：

| 需求 | 归属 |
|---|---|
| F1 默认排除的目录集合 | `exclude._is_excluded_dir` + `EXCLUDED_DIR_NAMES` |
| F2 排除只作用于搜索根之下 | `exclude.is_excluded` 的 `relative_to` + 目录分量语义 |
| F3 两个工具一致适用 | 两个工具共用 `exclude.is_excluded`；grep 的文件名过滤与排除判定串行叠加，互不覆盖 |
| F4 逐行扫描的效率与超长行语义 | `grep_tool._iter_lines` 重写（守卫与 EOF 分支原样保留） |
| N1 效率 | 由 F1（行数降到 1.1%）+ F4（吞吐对齐）共同达成 |
| N2 接口零变化 | 两个工具的 `name`/`description`/`parameters`/`read_only` 均不改；`_iter_lines` 签名与产出契约不变 |
| N3 不破坏 ch03 | 既有单测不动、必须继续通过；新增判定只在遍历循环内插 `continue`，不改变其余分支 |
| N4 不破坏 ch04~ch08 | 改动全部局限在 `tool/` 包内；不触碰 `permission/`（沙箱只校验搜索根，search 范围与它正交）、`agent/`、`mcp/`、`compact/` |
| N5 代码规范 | 沿用项目既有 `ruff format` / `ruff check` / `pytest` |

无缺口。

**接口完整性**——`is_excluded(path, root)` 与 `_iter_lines(file, max_line_chars)` 的签名、语义、边界行为均已在本文档定义，可据此独立实现任一模块。

**依赖清晰度**——依赖为单向：`glob_tool` / `grep_tool` → `exclude`。`exclude` 只依赖标准库，无环。

**矛盾检查**——无。唯一需要特意说明的是"路径不在根之下时返回 `False`"与 ch06 的"安全默认"原则方向相反，已在技术决策中写明确为有意为之及理由。
