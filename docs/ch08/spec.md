# 上下文管理 Spec

> 状态：用户已于 2026-09-19 审核通过，进入技术设计。本文件不代表已完成实现。
> 原始需求：本章 `target_desc_from_user.md` 及本次对话中的补充。

## 背景

PotatoCode 已支持多轮对话、连续工具调用、Anthropic / OpenAI 两种协议、
MCP 工具和终端交互。目前每次请求携带完整历史，工具结果持续累积；
API 返回的 usage 主要用于界面累计展示，尚未与历史边界一起留存。
现有系统没有统一的工具结果存盘、上下文预算检查、摘要恢复或手动压缩能力。
Skill 目前只有空的提示词扩展位置，尚无自动发现、选择和加载系统。

本章通过工具结果存盘预防单条内容过大，通过结构化摘要处理历史累积。
摘要可能失败，近期原文也可能独自超过窗口；这些情况下必须保留历史、
明确结束本轮，而不能无限重试或静默丢失用户内容。

## 目标

- 每次普通 API 请求前，依次执行轻量预防、完整请求预算检查和必要的摘要压缩。
- 优先压缩工具结果；近期用户消息保持原文，早期用户的重要要求在摘要中保留原话。
- 自动、紧急和 `/compact` 手动压缩共用切分、摘要、重建与失败处理规则。
- 保存每次 API 请求的 usage 与对应历史边界，用最近有效记录校准增量估算。
- 保持工具调用与结果配对、对话顺序、现有权限和取消行为，长会话能够继续工作。

## 方案取舍与已确认约定

两层策略采用原始需求给定的方案。以下比较只处理近期保留规则无法满足的边界：

| 方案 | 行为 | 取舍 |
| --- | --- | --- |
| 严格保留近期原文（用户已确认） | 无合法早期前缀时保留原文、跳过摘要；实际超限仍进入紧急压缩判定，无可摘要内容则报告无法执行 | 保留明确的消息下限和原文约束，但无法压缩任意超大输入 |
| 放宽近期下限 | 必要时降低 5 条或 10,000 token 下限，仍保留最新用户消息 | 可以处理更多短历史，但改变原始保留要求 |
| 分批处理早期历史 | 多次摘要再合并 | 能处理更大的历史，但增加调用成本与嵌套失败路径，本章不采用 |

本章采用以下已随需求审核通过的具体约定：

- 上下文窗口由当前 provider / 模型的显式配置提供，不猜测兼容端点的实际窗口；
  缺失或非法时提示补充配置，保留会话并阻止该模型发起请求。
- usage 保存在当前会话生命周期内；本章不新增跨进程的对话恢复。
- 存盘保存的是工具交付给会话的完整结果，保留已有工具内部的输出上限。
- 重建后的请求仍过大时，先减少附带的文件与 Skill 内容；仍无法容纳则停止，
  不擅自降低近期保留要求。
- 普通请求显式设置输出上限，默认 4,096 token；摘要请求显式设置输出上限，默认 20,000 token。
  允许按端点能力配置普通上限或调低摘要上限，摘要窗口预留仍固定为 20,000。

## 术语与预算

| 术语 | 定义 |
| --- | --- |
| 普通请求 | 推进用户任务的 LLM 请求，包含用户提交后的首轮及工具执行后的每次续调 |
| 摘要请求 | 为压缩早期历史发起的独立 LLM 请求，不执行工具、不递归触发另一次摘要 |
| 一条消息 | 会话内部的一条 user、assistant 或工具结果消息；一条工具结果消息可包含多个结果，不按 provider 序列化后的块数计数 |
| 历史总数 L | 当前待处理历史的消息数，不含 system；包含既有的摘要重建消息 |
| 近期数 N | 保留原文的连续末尾消息数；早期数另记为 M，禁止与 N 混用 |
| 窗口 C | 当前 provider / 模型配置的上下文窗口 token 上限，必须是大于 33,000 的整数 |
| 摘要输出预留 R | 20,000 token；包括临时分析草稿及正式摘要所消耗的输出预算 |
| 安全余量 S | 13,000 token |
| 自动触发阈值 T | `C - R - S`；估算输入达到 T，即触发自动压缩 |
| 完整请求输入 | system、环境、临时提醒、消息文本、工具调用参数、工具结果、工具定义及协议包装的全部输入 |

20,000 是摘要输出预留，不要求模型必须生成这么长的摘要。
普通请求输出上限记为 O，摘要请求输出上限记为 A；它们来自显式配置或上述应用默认值，
不是声称自动获知了模型能力。O 必须是小于 C 的正整数，A 必须是正整数且不大于 20,000。
若端点不支持设置的输出上限，显示可操作错误，不静默猜测另一个数值。
普通请求除按 T 触发外，还必须满足“完整输入 + O 不超过 C”；
输入虽低于 T，但输出余量不足时，也先尝试一次压缩。

## 功能需求

### F1：统一请求前检查

- 每次普通请求前，先对即将使用的历史执行 F2–F3，再按 F4–F6 检查与压缩。
  不只在用户提交时检查，也覆盖同一次用户任务中的工具续调。
- 使用轻量替换后的内容计算预算；已检查且未变动的内容允许复用检查结果。
- 摘要请求沿用轻量预防，但只执行自身的输入预算与有界重试，不能递归进入自动或紧急压缩。
- 只有工具执行与结果回灌完成、历史配对合法时才替换历史；不在工具执行中或等待批准时切分。

### F2：单个工具结果存盘

- 工具结果正文超过 50,000 字符时，将该结果全文保存到会话专属的本地文件。
  恰好 50,000 字符不触发单条存盘。
- 结果正文替换为原文前 1,500 字符的预览、截断说明、原始字符数及可读取的文件路径。
  路径与说明不占 1,500 字符预览额度，但计入后续聚合与 Token 预算。
- 字符按文本字符计数，不按 UTF-8 字节数计数；保留调用关联、结果顺序和错误标记。
  成功与失败的工具结果、内置与 MCP 工具使用同一规则。
- 保存成功才替换结果；失败时保留该结果原文、报告原因并停止本次待发送请求，
  不伪造可用路径或丢弃内容。再次检查已存盘的结果不重复创建文件或嵌套预览。
- 文件在后续轮次中可通过现有文件读取工具按需读取，遵循既有权限。
  不自动删除仍被会话引用的文件；本章不做磁盘配额和自动清理。

### F3：单条消息中的工具结果聚合限制

- 在 F2 完成后，计算同一条工具结果消息中所有结果正文的字符数之和，
  包含已替换正文中的预览、路径和说明，不聚合不同消息。
- 合计超过 200,000 字符时，从尚未存盘的结果中按当前字符数由大到小选择，
  对选中的结果执行 F2 的存盘与预览替换，直至合计不超过 200,000。
  相同长度按消息中的原始顺序选择；恰好 200,000 不触发。
- 已存盘结果不再次存盘；不能带来缩减的候选不反复处理。
  如果所有可缩减结果均已处理而合计仍超限，明确停止本轮并保留可恢复内容。
- 用户消息和助手文本不受这两项字符限制影响，不通过存盘预览改写它们。

### F4：逐次 usage 记录与近似 Token 估算

- 每次普通请求、摘要请求及重试，只要收到 usage，就保存输入、输出、缓存相关数值，
  关联请求序号、请求类型、provider / 模型、对应历史版本和起止消息边界。
  流中断或失败时收到的 usage 也可记录，但必须标明完成状态。
- 两协议分别按其 usage 语义归一化完整输入，计入缓存占用且不重复计算缓存。
  界面的累计消耗与当前上下文占用分别计算，不能累加历次完整输入作为当前历史大小。
- 对实际请求边界，可以准确查询当时 API 报告的输入和输出。
  这些记录是历史观测值，不等于任意消息前缀的精确 token 数，也不承诺输出 token
  全部等于下一次请求中保留的可见文本 token。
- 当前完整历史基于最近一个同模型、同历史版本且可复用的成功 usage 锚点估算；
  只对新增内容和请求组成的变化按字符数量估算，完整输入范围见术语表。
  无 usage 时按字符估算全部输入，缺失不能视为真实的零消耗。
- 摘要请求的 usage 只代表其早期前缀和摘要指令，不直接用作重建后普通请求的完整上下文锚点；
  它参与实际消耗统计，重建后的普通请求成功后才建立新的完整请求锚点。
- 工具结果替换、摘要重建或模型变化后，不直接复用已失效的完整历史锚点；
  可保留不受影响的历史边界记录，其余变化按字符重新估算，下一次成功 usage 再校准。
- 任意消息边界的切分预算允许估算，并标明“API 观测”与“估算”的区别。
  字符换算规则应确定、可复现，具体系数留给技术设计；本章不引入精确 tokenizer。

### F5：自动摘要触发与预算检查

- 轻量预防之后，完整请求输入估算达到 T 时，在普通请求发送前启动一次压缩事务。
  未达到 T 但“完整输入 + O 超过 C”时也先尝试压缩；两者均未命中则直接发送。
- 摘要请求使用当前选中的 provider / 模型，其完整输入不得超过 `C - 20,000`。
  该预算包含摘要指令、system、早期消息和包装开销，不能把全部额度都分给早期正文。
- 窗口配置缺失、非整数或不大于 33,000，以及 O / A 不符合术语表约束时，
  给出可操作的配置错误，不产生负阈值或无限压缩。
- 摘要后必须按 F8–F10 重新检查完整普通请求预算；摘要接口返回成功不等于可直接继续发送。

### F6：完整、连续且合法的历史切分

- 使用一个切点，早期是最前面的 M 条，近期是最后面的 N 条，始终满足 `M + N = L`。
  两部分不重叠、不遗漏，中间不得出现未处理的消息。
- 近期要求：N 不小于 5，近期估算 token 严格大于 10,000，第一条不是工具结果消息；
  工具调用与对应结果不能跨切点拆散。这些下限在自动、手动和紧急压缩中均保持。
- 不额外要求保留从最近用户消息开始的全部消息：单个用户任务可能产生很长的工具循环，
  允许将其中较早的部分纳入摘要，当前任务的用户要求按 F7 保留。
- 在满足近期要求、消息配对合法和摘要完整输入预算的切点中，选择 M 最大的切点。
  必要时增大 N、减小 M，把超出早期预算的消息原文并入近期。
- system 不参与消息数量，但参与请求预算。已有摘要重建消息属于历史，后续压缩时可再次摘要，
  不无限堆叠重建消息；实际仅替换本次选中的早期前缀。
- 不足 5 条、全部历史不超过 10,000 token、没有合法的非空早期前缀等情况下，
  不强行生成摘要。手动压缩提示“当前没有可压缩的早期消息”；
  自动检查保留原文并跳过本次摘要，如果“完整输入 + O 不超过 C”，允许继续普通请求。
  如果普通请求随后实际超限，仍进入 F12 的紧急压缩判定；若仍无可摘要内容，报告无法执行。
  预检已发现“完整输入 + O 超过 C”且无合法切点时，直接报告无法压缩，不发送已知超限请求。

### F7：结构化摘要及用户原话

- 摘要指令明确禁止调用工具、禁止继续执行原任务，并要求先生成临时分析草稿，再生成正式摘要。
  草稿与正式摘要可明确区分；草稿用后丢弃，不进入历史、终端显示或持久化日志。
- 请求不提供可调用的工具。若仍返回工具调用，不执行它，并将该次摘要视为失败。
- 正式摘要固定包含以下八项，无相关内容时明确写“无”：
  1. 用户的主要意图。
  2. 解决问题的思路和方法。
  3. 讨论过的关键技术点。
  4. 涉及的文件、关键代码片段。
  5. 用户说过的原话，不把工具结果或助手文本冒充用户原话。
  6. 还没完成的事情。
  7. 当前在做什么。
  8. 接下来打算做什么。
- 用户原话优先保留目标、约束、修正意见和未完成要求，逐字引用，不把改写的内容标成原话。
  近期用户内容全部留在原始消息中；早期原话在摘要预算允许范围内尽量保留，
  不承诺无限量逐字重注入全部历史用户消息。
- 二次摘要时区分原始用户输入与合成的 user 角色重建消息。
  旧摘要、文件和 Skill 文本不能因角色为 user 就变成“用户说过的话”或用户授权；
  仅可继承能追溯到原始用户输入的引文，当前任务要求优先保留。
- 摘要不得编造工具执行成功、已修改文件或未发生的用户决定。
  空摘要、缺少必需部分、草稿与摘要无法分离或输出被截断为不完整内容时，均视为失败。

### F8：摘要重建消息与原子替换

- 摘要成功且候选重建内容通过完整性与预算检查后，才替换早期 M 条消息。
  结果顺序为：system → 一条 user 角色的摘要重建消息 → 原文保留的近期 N 条消息。
- 重建消息依次包含：
  1. 摘要声明：会话延续此前的对话，因上下文空间不足，将早期 M 条消息压缩到这里。
  2. LLM 输出的正式摘要。
  3. 最近使用的文件及内容，最多 5 个，每个内容最多 10,000 字符。
  4. 使用过的 Skill 定义，所有定义正文合计最多 50,000 字符。
  5. 防幻觉提示：“以上内容为摘要重建的上下文，如需精确的代码，请重新读取源文件。”
- 手动触发但尚未达到阈值时，声明如实写“按用户要求整理上下文”，不声称已经发生空间不足。
- 最近文件和 Skill 没有可用记录时仍保留对应部分，注明“无可用记录”。
- 用户消息顺序、近期文本及工具调用配对保持不变；适配到两种协议后均为合法请求。
  user 角色的重建内容不替换或提升为系统指令，不改变权限或模式。
  会话需保留其合成来源，以供后续摘要识别。
- 失败、取消或候选重建内容不可用时，保留轻量预防完成后的全部消息，
  不提交半成品摘要或部分删除早期历史。

### F9：最近文件与 Skill 的来源

- 只跟踪本会话中成功读取、修改、写入的文件，以规范化路径去重，最近使用优先选择至多 5 个。
  失败或被拒绝的操作不计入；不从 shell / MCP 的任意文本输出猜测文件被访问。
- 文件内容来自已有授权下可获得的源文件内容；重读遵循既有权限，
  不能绕过拒绝规则、扩大授权或阻塞在新的权限申请上。
  文件删除、不可读或内容不足时保留路径及真实说明，不编造内容。
  超过 10,000 字符时保留开头片段并明确标记截断。
- 本章记录成功读取的 `SKILL.md` 及上层明确加载的 Skill 定义，
  以此作为可验证的“已使用 Skill”来源；普通提及名称不算加载。
  保留定义来源、最近使用顺序和实际加载版本；压缩掉其原始读取消息后记录仍可使用。
- 部分读取或工具截断时，只记录实际成功读取并交付给模型的内容、范围和截断状态，
  不把片段称为完整定义，不擅自补读未授权内容或拼接不同版本的片段。
- Skill 去重后按最近使用优先注入，总正文不超过 50,000 字符，截断或省略时标明。
  已作为 Skill 注入的文件不再在“最近文件”正文中重复注入。
- 不重新注入本地密钥配置或凭据；沿用项目已有访问约束。
  不新增 Skill 自动发现、选择、执行、安装或权限体系。

### F10：重建后的整体预算与无进展处理

- 把正式摘要、声明、文件、Skill、防幻觉提示、近期历史以及完整普通请求的其它输入一起估算。
  准备继续的请求必须低于 T，并满足该请求的实际输出预留。
- 文件 5 个、每个 10,000 字符和 Skill 50,000 字符都是上限，不是必须填满的目标。
  预算不足时先移除较旧的文件内容，再移除较旧的 Skill 内容，保留来源与省略说明。
  这不改变正式摘要和近期原文。
- 附带内容已缩减后仍不满足预算，或者重建未能减少上下文占用，则不提交该候选，
  结束本轮并说明原因。不得在同一请求前循环调用摘要以追逐阈值。
- 不用静默截断最新用户消息、孤立工具结果或删除近期消息的方式伪装压缩成功。

### F11：摘要重试与熔断

- 一次压缩事务最多调用摘要 API 3 次，即首次尝试加最多 2 次重试；
  上下文超限、网络错误、其它 API 错误及无效摘要共用额度，不能分别重置次数。
- 摘要因 `prompt_too_long` 失败时，在前一次切分基础上增加 N、减少 M。
  新早期内容的估算 token 至多为前一次的 90%，并在此条件及 F6 边界内选择最大的 M。
  被移出的消息原文归入近期，不删除；system 和固定摘要指令不冒充可减少的早期 token。
- 找不到可满足至少减少 10% 的合法非空早期前缀时，提前停止，不发送相同或空前缀继续重试。
- 网络和其它 API 错误重试时保持上次切点，避免因无关错误改变摘要范围。
  连续失败达到 3 次后熔断，不再调用摘要，也不发送明知超限的普通请求。
- 取消立即停止，不消耗剩余重试额度。摘要请求不会触发紧急压缩的递归入口；
  底层客户端的自动重试不得使实际摘要请求数超过上述上限。
- 熔断阻止当前用户请求内的进一步自动恢复；下一次用户提交或手动 `/compact`
  可开始新的有界事务。终端始终能够接受取消、退出及后续输入。

### F12：紧急压缩与原请求恢复

- 任意普通请求出现协议层可识别的上下文超限错误时，即使预估未达 T，
  也启动一次紧急压缩事务，执行 F6–F11；错误分类需覆盖两种协议，
  普通网络、鉴权或其它参数错误不冒充 `prompt_too_long`。
- 压缩成功且重建通过后，最多重发一次失败的普通请求，继续原任务；
  不重复追加用户消息，不重新执行已经完成的工具操作。
- 重发仍超限、没有可压缩前缀或摘要熔断时，停止本轮并报告；
  不形成“原请求失败 → 压缩 → 原请求失败 → 再压缩”的循环。
- 失败流中未完整确认的文本或工具调用不作为完成结果写入历史或执行。

### F13：手动压缩与终端反馈

- 空闲且已选择 provider 时，输入精确命令 `/compact` 触发一次压缩事务，
  不要求达到 T，先执行轻量预防，再复用 F6–F11。
- 命令自身不作为用户消息入历史；压缩成功后返回空闲，等待下一条输入，
  不自动继续执行用户任务或改变当前模式。
- 运行中、等待工具批准或正在压缩时不并发开启手动压缩，遵循现有输入忙碌行为。
- 自动、紧急、手动压缩均显示开始、成功、跳过、失败或取消的简要状态。
  成功时报告实际压缩的 M 条、保留的 N 条和压缩前后估算 token；
  重试时说明次数与失败类型，不展示临时分析草稿。
- 摘要 usage 纳入实际会话消耗显示，但与重建后上下文占用估算区分。
  Esc / Ctrl+C 能取消正在进行的压缩并回到可继续交互的状态。

## 非功能需求

- **N1：历史完整性。** 除明确的工具结果替换和成功摘要前缀替换外，不丢失、重排或改写历史；
  每个工具调用有对应结果，不重放已完成的副作用。
- **N2：协议一致性。** 两种协议遵循相同阈值、切分与熔断规则，缓存计数和错误格式在各自边界正确处理。
- **N3：有界与响应性。** 轻量检查无需调用模型；无进展立即终止；摘要实际尝试不超过 3 次；
  文件处理和网络等待不冻结终端，取消不会提交部分重建历史。
- **N4：数据来源可信。** 原文引述、文件和 Skill 均有会话来源；压缩不扩大文件或工具授权，
  不把摘要当成真实工具执行记录，日志不输出密钥或临时草稿。
- **N5：兼容性。** 既有普通/计划模式、权限、MCP、工具顺序、流式输出及取消能力不退化。
  新的上下文窗口配置要求需提供清晰说明和示例，不能把缺失值静默猜成模型真实上限。
- **N6：可验证。** 使用可控的 API usage、超限错误、文件失败与摘要输出验证边界；
  运行仓库要求的 Ruff、pytest，必要时 mypy，并在 Windows 用 Textual `App.run_test()` 验证完整交互。

## 不做的事

- 精确 tokenizer、逐条消息的 API 精确计数或机器学习摘要策略。
- 跨进程对话恢复、长期记忆、向量检索、后台摘要和额外的摘要模型路由。
- 自动推断兼容服务的实际窗口，或维护在线模型能力数据库。
- 多层递归摘要、分批摘要后再合并，以及无限自动恢复。
- 改变已有工具内部输出上限；存盘不恢复工具在返回之前已经截断的输出。
- 全量 Skill 系统、从任意命令输出推断文件操作、自动磁盘清理。
- 保证任意长度的单条用户输入或不可压缩近期内容都能装进有限窗口。
